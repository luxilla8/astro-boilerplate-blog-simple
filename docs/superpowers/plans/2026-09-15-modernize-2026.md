# 2026 Modernization Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Bring `astro-boilerplate-blog-simple` from Astro 5.16 / React 18 / ESLint 9 to Astro 7.3 / React 19 / ESLint 10 on Node 24, fix the red CI, close the template gaps, and install the site-standard security and indexability gates, so a fresh clone builds green and ships hardened by default.

**Architecture:** The upgrade is a sequence of independently green commits. Baseline first (fix what is broken today), then minor updates, then React 19 + Keystatic 6 while still on Astro 5, then the Astro 5→6 and 6→7 hops with exact pinned versions, then ESLint 10. After the stack is current, three hardening tasks add security headers, generated icons, a Keystatic production storage switch, the site-standard verify scripts, and a dependency-free smoke test wired into CI. Docs are updated last.

**Tech Stack:** Astro 7.3.2, `@astrojs/vercel` 11.0.10, `@astrojs/react` 6.0.5, `@astrojs/markdoc` 2.0.9, `@astrojs/sitemap` 3.7.4, `@astrojs/rss` 4.0.19, Keystatic core 0.6.9 (exact) + adapter 6.0.0, React 19.3.0, Tailwind 4.3.3, TypeScript 5.9.x, ESLint 10.10.0 + `eslint-plugin-astro` 3.1.0, Node 24.

**Spec:** `PLAN.md` (July 2026 roadmap, now superseded by this file) plus the research recorded in the Appendix below. Read the Appendix before starting: it records every version ceiling and every known breaking change, with sources.

## Global Constraints

- **Threat surface tier: T2** (astro-site-standard). Static site plus a newsletter form that posts to an external provider; no API routes of our own. The Keystatic admin routes are server-rendered but are dev-only until GitHub mode is configured, and then authenticated by GitHub. Re-tier if a future site adds its own endpoints.
- **Node 24** everywhere: `.nvmrc` = `24`, `package.json` `engines.node` = `>=22.22.3` (the floor set by `eslint-plugin-astro` 3.x), CI `node-version: 24`. Node 25 locally builds with a Vercel warning; that is acceptable.
- **TypeScript stays `^5.9.3`.** TypeScript 7 has no compiler API yet and breaks both `astro check` and `@typescript-eslint/parser`. TypeScript 6.0.3 is the highest version the tooling accepts but changes defaults; it is out of scope for this plan.
- **`@keystatic/core` is pinned exactly** (`0.6.9`, no caret) per its changelog, because its UI peer dependencies use tight pins.
- **`trailingSlash: 'always'`** in `astro.config.mjs`, matching the existing directory output and the `/blog/<id>/` URLs already emitted by the RSS, sitemap and llms.txt endpoints.
- **CSP ships via `vercel.json`**, not Astro's `security.csp`, scoped to every path except `/keystatic` and `/api/keystatic`. The only `is:inline` script (dark-mode guard) moves to an external file so `script-src 'self'` holds.
- **No `eslint-plugin-jsx-a11y`.** It is an optional peer of `eslint-plugin-astro` and its own peer range does not include ESLint 10, so installing it under npm fails on peer resolution.
- **Every task ends green:** `npm run lint && npm run check && npm run build` all exit 0 before the commit. From Task 8 onward `npm test` and the repo gate are added to that list.
- **Unknown breakage is reported, not patched.** Each upgrade task enumerates the errors it expects. Any build, check or lint error outside that list is new: stop, record the full error text in the task's commit message body or the PR, and ask before working around it.
- **Rollback for any upgrade task** is always the same and is exact:
  ```bash
  git checkout -- package.json package-lock.json && npm ci
  ```
- **Content and CMS schema are not touched.** `keystatic.config.ts` collections, `src/content.config.ts` schemas and the sample content stay as they are, except for the two edits named in Task 3 (Zod import) and Task 6 (storage switch).
- **Placeholders** (`example.com`, `Your Name`) may live only in `astro.config.mjs`, `src/content/site-settings.yaml`, `src/content/authors/default.yaml`, `.env.example` and the docs.

- [ ] **Step 2: Write the generator**

Create `scripts/generate-icons.mjs`:

```js
// Generates public/og-image.png (1200x630) and public/apple-touch-icon.png (180x180)
// from public/favicon.svg and the site name in src/content/site-settings.yaml.
// Run: npm run icons
import { readFile, writeFile } from 'node:fs/promises';
import sharp from 'sharp';

const settings = await readFile('src/content/site-settings.yaml', 'utf8');
const name = (settings.match(/^name:\s*(.+)$/m)?.[1] ?? 'Astro Blog').replace(/^["']|["']$/g, '');
const favicon = await readFile('public/favicon.svg');
const logo = await sharp(favicon).resize(160, 160).png().toBuffer();

const og = `<svg xmlns="http://www.w3.org/2000/svg" width="1200" height="630">
  <rect width="1200" height="630" fill="#0f172a"/>
  <text x="600" y="400" text-anchor="middle" font-family="Inter, system-ui, sans-serif" font-size="72" font-weight="700" fill="#ffffff">${name.replace(/&/g, '&amp;').replace(/</g, '&lt;')}</text>
</svg>`;

await sharp(Buffer.from(og))
  .composite([{ input: logo, top: 180, left: 520 }])
  .png()
  .toFile('public/og-image.png');

await sharp(favicon).resize(180, 180).flatten({ background: '#0f172a' }).png().toFile('public/apple-touch-icon.png');

console.log(`Generated og-image.png and apple-touch-icon.png for "${name}"`);
```

Add to `package.json` scripts:

```json
"icons": "node scripts/generate-icons.mjs"
```

```js
// Smoke test over the built output. No dependencies. Run: npm test (after npm run build)
import { readFile, access } from 'node:fs/promises';

const OUT = '.vercel/output/static';
let failures = 0;
const ok = (msg) => console.log(`PASS  ${msg}`);
const fail = (msg) => { console.log(`FAIL  ${msg}`); failures++; };

async function exists(path) {
  try { await access(`${OUT}/${path}`); return true; } catch { return false; }
}

const required = ['index.html', '404.html', 'rss.xml', 'sitemap-index.xml', 'sitemap-0.xml', 'llms.txt', 'robots.txt', 'blog/index.html', 'theme-init.js', 'og-image.png', 'apple-touch-icon.png'];
for (const f of required) (await exists(f)) ? ok(`${f} exists`) : fail(`${f} missing`);

const settings = await readFile('src/content/site-settings.yaml', 'utf8');
const siteName = (settings.match(/^name:\s*(.+)$/m)?.[1] ?? '').replace(/^["']|["']$/g, '');
const index = await readFile(`${OUT}/index.html`, 'utf8');

index.includes(siteName) ? ok(`index.html contains site name "${siteName}"`) : fail('index.html missing site name');
/<title>[^<]+<\/title>/.test(index) ? ok('index.html has <title>') : fail('index.html missing <title>');
/<meta name="description" content="[^"]+"/.test(index) ? ok('index.html has meta description') : fail('index.html missing meta description');
/<link rel="canonical" href="https?:\/\//.test(index) ? ok('index.html has canonical') : fail('index.html missing canonical');
index.includes('application/ld+json') ? ok('index.html has JSON-LD') : fail('index.html missing JSON-LD');
(index.match(/<h1[\s>]/g) ?? []).length === 1 ? ok('index.html has exactly one h1') : fail('index.html h1 count is not 1');
!/name="robots" content="noindex/.test(index) ? ok('index.html is indexable') : fail('index.html has noindex');
!index.includes('<script>') ? ok('index.html has no inline script blocks (CSP)') : fail('index.html has inline <script>');

const robots = await readFile(`${OUT}/robots.txt`, 'utf8');
/^Sitemap: https?:\/\/.+sitemap-index\.xml$/m.test(robots) ? ok('robots.txt has Sitemap line') : fail('robots.txt missing Sitemap line');

const notFound = await readFile(`${OUT}/404.html`, 'utf8');
/name="robots" content="noindex/.test(notFound) ? ok('404.html is noindex') : fail('404.html should be noindex');

console.log(`\n${failures === 0 ? 'SMOKE: PASS' : `SMOKE: FAIL (${failures})`}`);
process.exit(failures === 0 ? 0 : 1);
```
